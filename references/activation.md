# 由 Agent 执行的启动流程

## 对用户只保留一句话

主启动词：**几何小老师**。别名：开始几何辅导、打开几何自习室。也可直接说“几何小老师，讲这道题：……”。这些是自然语言触发，不要求用户输入斜杠命令。必须先让宿主加载/安装这个 Skill；把文件放在任意目录不等于已被宿主发现。

由 Agent 执行命令、读取任务和修正计划。正常回复只给画板入口和必要的题目/范围问题；不要向孩子展示 provider、文件名、JSON、校验日志或终端操作教程。

## 1. 确定运行方式

- 确认当前宿主、Python 3.10+、本地文件/终端与浏览器能力。使用当前项目的可写学习目录，例如 `learning-data/`；不要在只读 Skill 安装目录保存学习记录。
- 当前是 Codex，且已安装并登录 Codex CLI：默认使用同一个 Codex 的自动模式。Claude/CodeBuddy 同理，只有确认自身 CLI 能力时使用。不得仅因某个 CLI 存在就跨到另一个模型账号，也不自动登录或安装额外工具。
- WorkBuddy 或没有可用自动 CLI 的宿主：当前 Agent 直接生成与校验计划，使用 manual 文件交接。它不需要额外模型账号或 MCP。
- 能力不够时只解释实际缺少的能力。不要宣称普通聊天界面能执行本地程序。

## 2. 启动并打开

在 Skill 根目录执行，ABS 为已经选定的绝对学习目录：

```sh
python3 scripts/serve.py --workspace ABS --provider codex
```

上例仅适用于确认可用的 Codex 自动模式；通用模式改用 `--provider manual`。通过宿主可保持运行的终端/后台进程启动，读取服务实际输出的 URL，再用宿主浏览器打开。不要假定端口已空闲；必要时加 `--port 0` 获取实际地址。已有服务只有在核对属于本次学习目录与所选模式后才能复用，不杀死未知进程。

服务运行期间页面可用；停止服务后，保存的学习页面仍可离线回放。自动调用失败应保留题目/草稿并说明原因，不静默换账号。只有用户另行选择通用交接方式时才更换模式。

## 3. 处理题目

- 自动模式：页面提交后由服务调用模型、校验并加载，无需回聊天重复发指令。
- 通用模式：已有题目就直接处理。用户在画板提交新题后说“讲这道题”，读取当前学习目录的 `jobs/<id>/request.json` 与 `prompt.txt`，写该任务的 `plan.json`；由服务编译并显示。需要修正时读取 validation-error.log。不要把手工回填的示例当作模型调用。
- 宿主支持持续任务监听时，可在当前授权的辅导会话中处理队列；没有此能力时如实保留“讲这道题”这一步，不声称网页能自动唤醒聊天 Agent。
- 页面只需选择年级，教材可保留“不确定”。知识范围自动读取 `grade-defaults.json`，不询问单个定理或手填章节。聊天接题未指定年级时说明暂用默认八年级，继续处理；已有年级时沿用。宿主生成请求可调用 `scripts/grade_defaults.py` 的 `profile_for_grade()`，与页面共用同一默认表。

已有题目的现场演示使用 `--plan PLAN --request REQUEST --presentation CONTEXT`（无场景时省略最后一项），启动时重新校验并固定打开该题，不落到默认例题。核对浏览器标题、原照片和题目后再交付。

用户把题目直接发在聊天里也可完成整条流程：生成请求与计划，调用本地编译器，再打开生成的学习页。题目和范围齐备时不要要求用户再把相同内容搬到页面。
